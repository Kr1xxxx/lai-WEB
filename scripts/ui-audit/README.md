# 界面扫描脚本

每次改界面、发布网页试用版之前跑一遍。它把清单（`UI_CHECKLIST.md`）里能自动查的几项变成命令：

| 检查 | 查什么 | 判定 |
| --- | --- | --- |
| 被遮挡 | 每个按钮、文字、表格格子：取中心点和左右两个点，看最上层是不是它自己 | 左栏被遮挡必须是 0；其他页面的数量不能比 `baseline.json` 多 |
| 原生下拉框 | 页面上还剩几个没换成统一下拉的 `<select>` | 必须是 0 |
| 下拉框样式种类 | 按主题统计下拉触发框的高度、字号、字重、圆角、箭头有几种组合 | 只报告；现在是「客户模块 14 号／其他 13 号」×「32／36 高」几种 |
| 点击前后字体 | 逐个点开下拉、输入框、带弹出的按钮，再输入、再关闭，比较字号、字重、字体、行高、尺寸、字色 | 必须是 0 处变化（字色只允许变成主题主色） |
| 页面报错 | 扫描过程中的 JavaScript 报错 | 必须是 0 |

范围：17 个页面＋客户公海／查重／设置＋客户详情＋新建弹窗／抽屉；粉色、橙色、科技蓝三套主题（小满已去掉，D-029）；1440×900、1280×720、1440×640、1200×800、1024×800 五种窗口。
窄窗口（1200、1024）是 2026-10 加的：顶栏搜索框压住版本标签就是在 1150～1270 宽时才出现，原来的三种窗口都看不到。
这个脚本只看「元素自己的中心点是不是在最上层」，只压住一半的重叠发现不了，那类问题由下面的重叠扫描负责。

## 用法

```
python3 -I scripts/web-trial/rebuild.py --base 线上页面.html --old-ref 提交号 --out lai-web.html   # 先重建网页试用版
node scripts/web-trial/serve.cjs lai-web.html &
PLAYWRIGHT_CORE=/某处/node_modules/playwright-core node scripts/ui-audit/ui-audit.cjs
```

脚本需要网页试用版自带的示例数据（`LaiWebTrialDemoSeed`），所以对着它跑，不能对着本机数据服务跑。
`playwright-core` 装在仓库之外；Chromium 默认 `/opt/pw-browsers/chromium`，可用 `CHROMIUM` 改。

常用选项：`--themes pink` `--views 1440x900` `--routes customers,order-list` 缩小范围；`--no-font` 跳过最慢的点击前后字体检查；`--out DIR` 指定报告目录（里面的 `report.json` 有每一处的详情）。
完整选项见脚本开头的注释。退出码 0 通过、1 有新增问题、2 脚本出错。

## 重叠扫描（overlap-sweep）

`overlap-sweep.cjs` 专门找三类界面问题，窗口宽度扫 1024、1152、1200、1280、1366、1440、1680、1920（高 800，1440 再加高 900），三套主题，所有页面：

| 种类 | 查什么 | 判定 |
| --- | --- | --- |
| 重叠 | 两个看得见的小元素（按钮、链接、输入框、文字、图标、徽标）互相压住超过 2px，并且在重叠处取样确认有一个盖住了另一个（不管谁包含谁） | 必须是 0 |
| 切字 | 文字被切掉又没有省略号：自己 overflow 隐藏装不下，或被外层 overflow 隐藏的容器切掉一部分 | 必须是 0 |
| 伸出 | 元素伸出窗口左右边缘，或整个页面出现横向滚动条 | 必须是 0 |

页面清单：ui-audit 的 17 个页面＋左侧菜单和其他模块登记的全部页面＋客户公海／查重／设置／回收站＋客户详情＋每个页面里的标签切换（看板｜列表、按月｜按季度……逐个点开）＋新建弹窗／抽屉＋点开才出现的小菜单（搜索范围、账号、新建、下拉、「⋮」、左栏悬停菜单；只检查刚弹出的那一块）。
滚动区里被滚出去的内容、折叠的内容不算；可以滚动的容器（overflow: auto／scroll）里需要滚动才能看到的内容不算切字。

```
node scripts/web-trial/serve.cjs lai-web.html 8791 &
PLAYWRIGHT_CORE=/某处/node_modules/playwright-core node scripts/ui-audit/overlap-sweep.cjs --url http://127.0.0.1:8791/ --out /某处/sweep
```

常用选项：`--themes pink` `--widths 1024,1200` 或 `--sizes 1200x800` `--routes customers,order-list` 缩小范围；`--no-dialogs` 不开弹窗和小菜单；`--no-tabs` 不点标签切换；`--stress` 先把示例数据里的公司名、联系人名拉长（真实客户名常常很长，只对网页试用版有效）；`--workers 4` 同时开几个页面；`--fail` 有问题时以退出码 1 结束。
默认全量（3 主题 × 9 种窗口，约 2000 个页面状态）约 6.5 分钟（4 核）；`--no-tabs` 约 3 分钟。输出：摘要表、按规则统计的白名单命中数和样例、每一种问题一行；`--out` 目录里的 `overlap-report.json` 有每一处的页面｜主题｜窗口｜种类｜两个元素（选择器＋文字）｜位置。
同一处问题在不同窗口、主题下合并成一种。不依赖基线：目标就是 0。

**白名单**只有一处：`overlap-checks.js` 开头的 `OVERLAP_ALLOW`／`CLIPPED_ALLOW`／`OFFSCREEN_ALLOW`，每条写明原因（数字角标压在图标上、冻结的操作列、输入框里的下拉箭头、环形图里的文字、排序小三角）。
加新规则前先确认真的是故意的；规则命中数和样例会在每次扫描结尾打印出来，可以看规则有没有放得太宽。

同一套检查（`overlap-checks.js` 和 `overlap-sweep-lib.cjs`）也在自动测试 `tests/e2e/overlap-sweep.e2e.mjs` 里跑：真实后端＋示例数据（公司名、联系人名故意拉长），粉色和科技蓝两套配色，宽度 1024、1200、1366、1680，约 110 秒；另有一个自检，往页面里塞一个重叠、一个被切掉的字、一个伸出窗口的字，检查器必须报出来（防止检查器自己坏了还显示通过）。

## 样式普查（census）

`census.cjs` 数一数页面上实际用了几种字号、字重、文字颜色、圆角、阴影、按钮样式（高×字号×字重×圆角×底色×边框×字色）、输入框样式、表头样式、标题样式，以及 12px 以下的文字有多少处。范围：ui-audit 的页面清单（17 页）＋客户详情＋新建客户／订单／商机；1440×900；默认粉色和科技蓝两套，各算各的。
种类越多界面越乱；D-028 的组件套件（`src/ui-kit.css`）一页页迁过去，这些数字只能往下走。

```
node scripts/web-trial/serve.cjs lai-web.html 8861 &
PLAYWRIGHT_CORE=/某处/node_modules/playwright-core node scripts/ui-audit/census.cjs --url http://127.0.0.1:8861/ --check
```

`--check` 和 `census-baseline.json` 比，任何一项变多就以退出码 1 结束；`--out FILE` 写出每一种样式和出现次数（找「多出来的那一种」用）；数字确实变少后用 `--write-baseline` 更新基线。约 1 分钟。

## 基线

`baseline.json` 记录「已核实不算问题」的被遮挡数量，例如客户表格冻结在右边的操作列压住后面的列、折叠起来的客群子分组。
只有在确认现有的每一处都是已知、可接受时，才用 `--write-baseline` 更新它，并在 VALIDATION.md 里写明原因。

## 局限

- 1024 宽只在浏览器窗口拖窄时出现；它仍然要求干净。
- 在无头 Chromium 里跑，看不到真实浏览器里的系统下拉菜单、系统日期选择，这些仍要在真实浏览器里确认（清单 E20）。
- 被遮挡检查在窗口很矮时会把「滚动区里被裁掉的内容」误报成遮挡；发现时先把那个区域滚到底看一眼再下结论。
